GOGOGO CLI

cmd/gogogo · stdlib-only, no deps

  • --run — scaffold a repo and run it, one command
  • advise — which lib or language fits the use-case
  • --dry-run — preview the plan as JSON, zero changes
  • --yes — scaffold, trim, prove it builds
  • add — bring a trimmed unit back
  • --check — verify markers, catch drift

Pin --no-tui --yes · never delete on an assumption

GOGOGO-MCP

cmd/gogogo-mcp · stdio, no port, no deploy

  • advise_stack — same guidance as advise
  • capabilities_list — full capability registry
  • trim_plan — preview, changes nothing
  • trim_apply — scaffold, needs confirm:true
  • check_tree — drift verdict per unit
  • add_unit — restore a unit, needs confirm:true

Prerequisite — install the binary, once

curl -sSfL https://raw.githubusercontent.com/calionauta/gogogo/master/install.sh | sh

Puts gogogo + gogogo-mcp in ~/.local/bin (or build from source: cd cmd/gogogo-mcp && go build -o gogogo-mcp .). Below, replace ~ with your absolute home path (echo $HOME) — clients spawn without a shell, so it may not expand.

{ "mcpServers": { "gogogo": { "command": "~/.local/bin/gogogo-mcp" } } }

Save as .mcp.json in your project (shared with the team), or run claude mcp add gogogo -- ~/.local/bin/gogogo-mcp for just you. Verify: claude mcp list, then restart Claude Code.

[mcp_servers.gogogo]
command = "~/.local/bin/gogogo-mcp"

In ~/.codex/config.toml (every project) or .codex/config.toml (this project, must be trusted). Verify: /mcp in session, or codex mcp list.

opencode mcp add gogogo -- ~/.local/bin/gogogo-mcp

Or in opencode.json: "mcp": {"gogogo": {"type": "local", "command": ["~/.local/bin/gogogo-mcp"]}}. Verify: opencode mcp list.

pi mcp add gogogo -- ~/.local/bin/gogogo-mcp

Pi 1.0 reads the standard mcpServers format too — migrating from another client just works. Verify: pi mcp list (exits 1 on invalid entries).

What makes it different

Everything async your app will need.
Already inside.

Every web app eventually needs a queue, a workflow runtime, a collaboration layer, a realtime layer, and an owner for shared state. They solve different problems, so gogogo compiles all of them into one build — and lets you switch each off with a single environment variable when you don't need it.

Background jobs that update the UI

goqite + SSE Hub

Always on. Work longer than ~50ms goes here instead of blocking a request — progress streams back to the browser.

Workflows that survive a restart

DagNats over JetStream

Declarative JSON. Kill the server mid-run; it resumes at the last incomplete step.

Collaboration without data loss

Loro CRDT

Offline edits merge with no last-write-wins loss. Ops converge idempotently.

Live record updates, scoped per user

PocketBase realtime

The collection's own access rules decide who sees what — no extra channel to secure.

Ephemeral UI signals

SSE Hub over Datastar

Toasts, client counts, workflow progress — signals, not database-shaped events.

Broadcast across instances

NATS JetStream

Run two or more instances behind a load balancer and records converge. Safe to enable on one.

Room ownership without races

GoAkt grains

One addressable owner per room: heartbeat roster plus an exactly-one presenter lock, supervised with restart budget.

Seven layers, one make build. No build tags, no stub files, no matrix. Read the async layers doc →

Safe to trim

Delete what you don't need, without guessing.

Every file in the codebase carries a SCOPE annotation on two axes: where it lives, and what happens if you delete it. A linter enforces it, so you never have to guess whether a directory is load-bearing.

Core

The binary does not work without it.

config · db · internal/queue
internal/secrets · features/app
router · web/resources

Customize, never remove.

Plugin

The binary works but loses a capability.

internal/nats · internal/dagnats
internal/llm · internal/collab
internal/datastar · internal/goakt
web/skins

Swap, or delete + remove the wiring call.

Feature

A demo or add-on.

features/room · features/notes
features/landing · features/config
router/onboarding_dagnats.go

Keep as reference, then remove.

The exception

Go for everything. Zig only as an exception.

Zig enters in one case: a proven native need — a profiled hot kernel, a codec, an OS integration. Everything else stays Go.
