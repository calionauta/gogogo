The other axis

The code has levels.
The runtime has layers.

A capability is not one folder. Real-time multi-user is the sum of the collaboration, live-record, signal, broadcast and room rows; durable workflows is DagNats; offline-capable writes are the mode below.

Offline-capable writes are a mode, not one of the seven

Writes go offline; reads stay server-owned. A mutation is stored in a durable outbox before it leaves the tab, and replayed on reconnect; the server dedupes by idem_key. Reads are queries — a view you never synced is refused, not answered from a stale replica. The desktop build is the exception: a NATS Leaf Node keeps a local JetStream replica, so reads work offline there too.

Switch OFFLINE_SYNC_ENABLED=false disables the Service Worker app-shell cache and the NATS CRUD proxy together. The outbox is never gated — losing a queued write is worse than the cache it protects.

Lives in Features Plugins Core · Try it disconnect, edit, reconnect.

The exception

Go for everything.
Zig only by exception.

Zig enters in one case: a proven native need — a profiled hot kernel, a codec, an OS integration. Everything else stays Go. The burden of proof is on the native case, and the kernel is removable in minutes.

Start here

Run. Ship. Summon.

One install puts the binary and the MCP server on your PATH. Then wire your agent. Humans type; agents call.

  1. 01

    Install the binary

    Needs curl and git. Puts gogogo and gogogo-mcp in ~/.local/bin.

    curl -sSfL https://raw.githubusercontent.com/calionauta/gogogo/master/install.sh | sh

  2. 02

    Scaffold and run

    Rename, trim the units you skipped, and prove it builds. Then open localhost:8080.

    gogogo --run

  3. 03

    Wire your agent

    One block in your client config. Clients spawn without a shell, so replace ~ with your absolute home path (echo $HOME).

    { "mcpServers": { "gogogo": { "command": "/home/you/.local/bin/gogogo-mcp" } } }

    Save as .mcp.json in your project, or run claude mcp add gogogo -- ~/.local/bin/gogogo-mcp.

    [mcp_servers.gogogo]
command = "/home/you/.local/bin/gogogo-mcp"

    In ~/.codex/config.toml (every project) or .codex/config.toml (this project).

    opencode mcp add gogogo -- ~/.local/bin/gogogo-mcp

    Or in opencode.json: "mcp": {"gogogo": {"type": "local", "command": ["/home/you/.local/bin/gogogo-mcp"]}}.

    pi mcp add gogogo -- ~/.local/bin/gogogo-mcp

    Pi reads the standard mcpServers format too — migrating from another client just works.
