What makes it different

Most templates make you pick one async strategy.
This one ships six.

Every web app eventually needs a queue, a workflow runtime, a collaboration layer, and a realtime layer. They solve different problems, so gogogo compiles all of them into one build — and lets you switch each off with a single environment variable when you don't need it.

goqite

background jobs + SSE hub

Always on. Work that takes more than ~50ms goes here instead of blocking a request.

DagNats

durable multi-step workflows

Declarative JSON over JetStream. Kill the server mid-run; it resumes at the last incomplete step.

Loro CRDT

conflict-free collaborative state

Offline edits merge with no last-write-wins data loss. Ops converge idempotently.

PB realtime

record-change push

PocketBase's native channel, scoped per user by the collection's own access rules.

SSE Hub

ephemeral signals

Toasts, client counts, workflow progress — over Datastar's SSE protocol, not database-shaped.

JetStream

cross-instance broadcast

Run two or more instances behind a load balancer and records converge. Safe to enable on one.

Out of the box

Capabilities, and how to switch each one off.

Every capability is always compiled. Infrastructure opts out with an environment variable; product features opt out by deleting a package and its one wiring call.

Todo app + realtime

Full CRUD. Database actions stream through PocketBase realtime, scoped per user by the collection's access rule. Toasts, client count, and AI suggestions ride the SSE Hub.

Queue + retry

Background jobs with exponential backoff and jitter. SSE-aware: a retry emits a lastRetry signal so the UI can show "retrying…".

Durable workflows

WelcomeOnboarding creates example todos through DagNats. Stop the process mid-run and restart — it picks up where it left off.

Collaborative whiteboard

Loro CRDT canvas with Rough.js, presence cursors, offline outbox replay, and PocketBase-persisted snapshots.

Hybrid offline sync

A Service Worker queues mutations in IndexedDB and replays them on reconnect; the desktop build does it with a NATS Leaf Node. Server-side idempotency means replays never duplicate.

Three pluggable skins

DaisyUI (default), Basecoat, and Morpheus — all compiled into the same binary, switchable per process or per request.

AI credits + BYOK

Optional billing that shares PocketBase's SQLite file: reserve/settle ledger, monthly entitlements, Stripe top-ups, and encrypted per-user keys.

Admin surfaces

PocketBase's admin UI at /_/, a read-only config view at /config, and the DagNats workflow console — all from one binary.

Safe to trim

Delete what you don't need, without guessing.

Every file in the codebase carries a SCOPE annotation on two axes: where it lives, and what happens if you delete it. A linter enforces it, so you never have to guess whether a directory is load-bearing.

Start here

Clone it. Rename it. Ship it.

gh repo create my-app --template \
  calionauta/gogogo-fullstack-template --clone
cd my-app
make rename NAME=my-app
make dev

A fresh copy still carries the template's name in ~360 places across ~130 files. make rename rewrites all of them and then compiles, so a half-renamed tree cannot slip through. Then open localhost:8080 for the landing page and localhost:8080/todo for the demo (demo@demo.app / demo).
