# MyGo shell: the spike, the proof, and how to build it

Reviewed: 2026-11-08. Status: spike validated — `cmd/mygo` ships the loopback shell; the native `ui.View` over `Service` is a deliberate follow-up, not a gap.

This page captures what the 2026-11-08 MyGo spike proved, so the next operator does not relearn it. It answers one question: **can gogogo ship a MyGo version, and what does it take?** Short answer: yes, as a peer shell over the same flat stack — with `ENVIRONMENT=dev` (`SecureCookies=false`) and an isolated database, the MyGo webview persists the `gogogo_auth` cookie (`SameSite=Lax`), serves `GET /api/todos` 200, and `POST` returns the SSE `datastar-patch` with `itemCount 1`. The 401 that blocked earlier attempts was `Secure=true` or a stale DB/socket lock, not a MyGo defect.

## What was proven (evidence, not opinion)

Prior sessions (#712, #713 in Engram) ran two spikes outside the repo (`/tmp/mygo-spike/counter`, `/tmp/mygo-spike/shared`):

- `counter` (`module counter`, `github.com/egoist/mygo v0.8.3`, `go 1.27.3`): native `ui.View` window on the main thread, server stays marshalled to the main thread.
- `shared` (`module shared`, same pin): **one Go source of truth** — `Todos.Add/List` behind `mygo.Bind(store)` **and** `ui.View(store.view)` **and** a loopback `http.Listen("tcp", "127.0.0.1:0")` page (server-rendered, Datastar-like, no Vite/Bun). `vet/build/test` green.
- Full app proof (session `ses_e447d6a28ffe2rlY53r61faNBC`): with `ENVIRONMENT=dev` + isolated `TURSO_DB_PATH`, the real gogogo flat stack booted inside the MyGo webview and completed the E2E: cookie persisted, list 200, mutation SSE patch, no Vite/SPA.

The shipped `cmd/mygo` is that proof turned into a target: `server.StartChi` on an ephemeral loopback port, window at `desktopboot.WebviewURL(host, port)`, `SecureCookies=false`, `LicenseGate=true`, `ScopeInstanceIdentity` — the same decisions `cmd/desktop` documents in `docs/desktop-mobile.md`.

## The two MyGo paths (and which is core)

MyGo gives two ways to show the app, and they are not interchangeable:

| Path | What it is | When it is core |
|---|---|---|
| **URL loopback webview** (`WindowOptions.URL` + `Page.TrustedOrigins`) | Same Templ/Datastar frontend, same SSE/cookies, no `frontendDist`/Vite/Bun. | **Core path (v1).** This is what `cmd/mygo` ships. |
| **Native `ui.View` + `Bind(store)`** (`Content: ui.View(...)`) | MyGo draws the UI; `store` (`Todos.Add/List`) is the single source through `Bind`. | **Follow-up.** Needs `features/todo/service` wired through `desktopboot` + `ncruces` (`sqlite3`), see driver note below. `Bind` is the optional RPC seam, never the core path (see `docs/service-layer.md`). |

A window is one or the other (`URL` or `Content`), never both. The spike opened **both** windows in one app (`web-loopback` + `native-shared`) to prove they share the store — `cmd/mygo` ships the URL window; the native window is the follow-up gated on the service wiring.

## Driver matrix (why CGO stays on for the loopback shell)

- `cmd/mygo` (URL loopback) boots `StartChi`, which opens **tursogo** (`internal/db/driver_other.go`, `!android`). That needs `CGO_ENABLED=1` on macOS/Linux (Xcode CLT / GTK-WebKit headers are the same requirement `cmd/desktop` documents). MyGo itself is pure Go (`purego`), but the backend is not zero-CGO on this path.
- A future native `ui.View` shell that calls `Service` directly **without HTTP** should follow `cmd/gui`: open through `ncruces/go-sqlite3` (`sqlite3`) via `desktopboot.MigrateAll/NewAuth`, never `internal/db` (which links tursogo/purego and collides with goffi at `CGO_ENABLED=0`). Then `make mygo-native` can build `CGO_ENABLED=0`.
- Do **not** put both drivers in one binary hoping the OS resolves it. One shell, one driver.

## Build recipe (copy-paste)

```bash
# 1. Preflight (read-only, JSON for agents)
go run ./cmd/gogogo doctor --json
go run ./cmd/gogogo generate --check

# 2. Build the MyGo shell (local only, no CI — like desktop/gui)
make mygo           # → build/mygo/gogogo-mygo (CGO on, macOS CLT suffices)
make run-mygo       # build, then open the window

# 3. Fresh-profile E2E (isolated DB, Secure off — the #713 proof shape)
ENVIRONMENT=dev TURSO_DB_PATH=$(mktemp -u)/mygo.db ./build/mygo/gogogo-mygo

# 4. Packaging (optional, needs the mygo CLI)
go tool github.com/egoist/mygo/cmd/mygo build ./cmd/mygo   # reads cmd/mygo/mygo.json; .app/.dmg under build/
```

Prerequisites: macOS Xcode Command Line Tools (`xcode-select --install`) or Linux `build-essential pkg-config libgtk-4-dev libwebkitgtk-6.0-dev` for the tursogo link. The `mygo` CLI (`go tool` above, or `tool.mygo` in `doctor`) is only needed for packaging; `make mygo` is plain `go build`.

## Auth: own backend vs federated (same rule as Wails)

- **First-party `gogogo_auth`** stays inside the loopback webview (the app is the identity provider — no credential leaves the machine to a third party). Keep `SecureCookies=false` over `127.0.0.1`, or every page renders logged out (WebKit drops `Secure` over `http`).
- **Federated OAuth** (Google/GitHub) **must open the system browser** (RFC 8252, PKCE S256, loopback callback) — never inside the MyGo webview. Full rule: `docs/desktop-mobile.md § Desktop authentication strategy`.

## Automation limits (measured, read `AUTOMATION.md` from the spike)

- Web window (`URL`) **has no element tree** — `snapshot` fails. Use `eval` (`document.title`, `document.body.innerText`) and `screenshot` via `mygo-automation` (`github.com/egoist/mygo/plugins/automation`, build tag `e2e`).
- Native window (`Content`) **has elements** — `snapshot -i`, then `press @eN` (refs are per-frame; re-snapshot before every press).
- Session: `mygo-automation --session mygo open --socket /tmp/app.sock` (isolation: one socket per app/profile — a stale socket + DB lock is the classic false "MyGo is broken" signal).

## Gaps closed / open

- **Closed:** webview cookie + SSE + `Idempotency-Key` replay (real proof, not headless guess); `doctor` (`zig` warn, `desktop.sdk` via `xcode-select -p` — CLT passes, `Xcode.app` not required); strategy question in `docs/desktop-mobile.md`; `cmd/mygo` target + `doctor` `tool.mygo` check; `scripts/web-packages.sh` exclusion so web CI stays fast; single-instance parity via `RequestSingleInstanceLock` (app-wide, before boot); `make mygo-smoke` window gate (`scripts/mygo-smoke.sh`, mirrors `desktop-smoke.sh`).
- **Open (follow-ups, do not block v1):** native `ui.View` over `todo.Service` (`CGO_ENABLED=0` + `ncruces`); two-profile coexistence (MyGo lock is app-wide, unlike Wails DB-scoped — second profile exits cleanly); Android (MyGo has no Android path — Wails `cmd/mobile` stays the opt-in); code signing/notarization for a distributed `.app` (same swamp as Wails cross previews — local convenience until an operator owns it).

## Dependency trade-off (one line for the PR body)

`go get github.com/egoist/mygo@v0.8.3` (+ `purego`, `typesetting`, `image`) — pure-Go shell, no CGO/native floor raise; binary cost is paid only by `cmd/mygo` (excluded from web CI), not by `cmd/web`.
